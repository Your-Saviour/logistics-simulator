# Manufacturing OT V2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement SIMU-77 operator visibility, diagnosis, repeatable observational scenarios and an evidence-based simulator decision.

**Architecture:** Manufacturing's authenticated API remains the only command authority. Keep OpenPLC, equipment and editable FUXA unchanged; add an Angular equipment workspace. Persist bounded, grant-correlated observations and alarm episodes in new migration 017. Synthetic analogue profiles are explicitly observational and never affect completion.

**Tech Stack:** Java/Spring/PostgreSQL, Angular, existing Docker/OpenPLC/FUXA, containerised Playwright.

**Spec:** https://ctfittwo.atlassian.net/browse/SIMU-77. User delegated design and implementation decisions on 26 October 2026.

## Global constraints

- Build/test only in Docker through scripts/docker_guard.py; preserve the 20 GiB reserve.
- Preserve actual-grant, run/epoch, material lineage and exact command retry semantics.
- Preserve existing FUXA projects and OT-disabled operation; no live cutover.
- Work in the supplied checkout, preserving unrelated untracked files.

## Review focus

- Missing, old or failed observations disable operation and break trend lines.
- Scope changes clear displayed data and cannot retarget an uncertain command.
- Alarm acknowledgement cannot restore equipment, reset a latch or start production.
- Scenario noise is repeatable for a seed and simulation time; no wall-clock production stepping.
- History is bounded and duplicates cannot create another observation or alarm episode.
