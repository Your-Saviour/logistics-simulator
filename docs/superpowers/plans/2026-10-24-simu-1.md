# SIMU-1 application bootstrap implementation plan

> Execute inline with superpowers:executing-plans. CyberLab integration is explicitly excluded by the user.

**Goal:** Five independently deployable application skeletons with durable sample work and grant-gated clocks.
**Architecture:** Build-time shared Python and React source, independent service processes, PostgreSQL databases, RabbitMQ queues and credentials per application. Four business controllers choose explicit local or HELICS drivers; twin starts with no sources.
**Tech stack:** Python 3.12, FastAPI, psycopg, pika, HELICS; React/TypeScript, Vite; PostgreSQL 17, RabbitMQ 4; Docker Compose.
**Spec:** ../specs/2026-10-24-logistics-simulator-design.md and SIMU-1. Scope is bootstrap, not departmental V1 workflows.

## Constraints and review focus

- No adjacent repository changes, cloud resources, production deployment or external messages.
- Each website owns its identity, API and database. Twin cannot control business time.
- Exactly one explicit provider per boundary. No connected-to-synthetic failure fallback.
- Run and epoch fencing; bounded retries; database transactions own sample effects and deduplication.
- Concurrent workers, restart between publish/commit/ack, held/late work, malformed inputs and disconnected peers must fail closed.
